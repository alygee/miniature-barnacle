# Архитектура

Для тех, кто будет сопровождать и расширять плагин. Пользовательская часть — в [README](../README.md),
диагностика — в [operations.md](operations.md), обоснование решений — в [спецификации](superpowers/specs/2026-09-10-drone-telegram-mtproto-design.md).

## Зачем это устроено именно так

Плагин заменяет Go-программу [appleboy/drone-telegram](https://github.com/appleboy/drone-telegram).
Оригинал ходит в Bot API по HTTPS; здесь используется MTProto через локальный MTProxy
([tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy)), который туннелирует MTProto в WebSocket.
Отсюда два следствия, определяющие почти весь код:

1. **Совместимость обязана быть побуквенной.** Существующий `.drone.yml` должен работать после замены  образа и добавления четырёх параметров, а шаблоны — давать то же сообщение. Поэтому в коде живут порты библиотек Go: приведения типов, формат `time.Duration`, Go-layout дат, правила поиска полей шаблонизатора raymond.
2. **Сервер не разбирает разметку.** В Bot API есть `parse_mode`; в MTProto клиент сам обязан превратить текст в список `MessageEntity`. Поэтому в проекте есть собственный парсер.

Весь `src/` — 1473 строки. Каждый файл имеет одну ответственность и не знает о слоях выше.

Зависимости идут только вверх по таблице: `markdown.ts` ничего не знает о teleproto, `telegram.ts` — о шаблонах, а `main.ts` получает все побочные эффекты через `MainDeps` и поэтому тестируется без сети.

## Поток отправки

Порядок важен: всё, что может упасть без сети, падает до подключения.

1. **разбор команды** — `argv[0]`: пусто или `send` → отправка, `session` → печать строки сессии.
2. **`loadConfig`** — обязательные параметры, запрет медиа-параметров, проверка proxy-секрета.
   Здесь же строится редактор секретов для логов.
3. **этап `render`** — `loadCiContext` даёт переменные сборки, `renderMessage` выполняет пайплайн
   шаблона, `formatMessage` превращает разметку в entities. Пустой результат → предупреждение и код 0.
4. **получатели** — `parseTo`. Пустой список → предупреждение и код 0. До сети дело не доходит.
5. **этап `proxy`** — если задан `proxy_host`, `waitForPort` ждёт, пока сервис начнёт принимать
   соединения: в пайплайне он стартует параллельно со шагом.
6. **этап `login`** — `connectBot`: `dns.lookup` по имени сервиса, клиент teleproto с `MTProxy: true`,
   `start({ botAuthToken })`.
7. **этап `send`** — по получателю за раз. Ошибка одного не останавливает остальных; итоговый код 1,
   если хоть одна отправка не удалась.
8. **завершение** — `close()` в `finally`, затем явный `process.exit`: teleproto оставляет живые таймеры.

Режим `session` короче: ожидание proxy, логин, печать `exportSession()` в stdout, код 0. Полученную
строку передают потом в параметр `session`, чтобы не логиниться при каждой сборке.

## Ключевые решения

**Свой парсер Markdown.** `markdown.ts` — построчный порт легаси-функции `parse_markdown` из tdlib, той самой, что стоит за `parse_mode=Markdown` в Bot API. Готовых тестовых наборов у неё нет: кейсы в репозитории tdlib проверяют MarkdownV2. Поэтому таблица кейсов в `test/markdown.test.ts` выведена из алгоритма, а нормализация ссылок сверена с кейсами `[…](telegram.org)` из тестов tdlib.

Два отклонения от tdlib сделаны намеренно:
- `\_` считается литеральным `_` **везде**, включая текст сущности и URL. Так имя ветки `fix_login` остаётся читаемым в тексте ссылки и в блоке кода, а ссылки на репозитории с `_` не ломаются.
- Незакрытая сущность выводит свой открывающий символ как текст, вместо того чтобы завалить всё сообщение. Звёздочка в сообщении коммита не должна стоить вам уведомления.

**Порядок экранирования.** `_` экранируется до рендера и только вне `{{…}}`. Оригинал экранирует и
внутри, из-за чего `{{tpl.deploy_env}}` ломает разбор шаблона. Следствие порядка: `_курсив_` в
markdown-режиме не работает — ровно как в оригинале.

**Двойные ключи контекста.** Шаблонизатор Go raymond ищет поле структуры по точному имени или по
`strings.Title(name)`. Поэтому `buildTemplateContext` кладёт каждое поле под двумя ключами —
`FullName` и `fullName`. Отсюда же следует, что `{{repo.fullname}}` рендерится пустым: это не баг.
`github` добавлен псевдонимом, которого у raymond не было, а `config` в контекст не попадает намеренно.

**Запас у дедлайна.** `withDeadline` в `main.ts` срабатывает на `DEADLINE_GRACE_MS = 1000` позже
дедлайна. Без запаса общий таймаут выигрывает гонку у `waitForPort`, и оператор вместо
`proxy tg-ws-proxy:1443 is not reachable after 60s` видит безликое `timed out`.

**Границы секретов — их две.**
- `redact.ts` подменяет токен, `api_hash`, proxy-секрет и сессию на `<redacted>` во всём, что уходит
  в stdout и stderr.
- `template.ts` фильтрует окружение, которое получают хелперы `env`/`expandenv`:
  `SECRET_SETTING = /^(PLUGIN_|TELEGRAM_|INPUT_)(TOKEN|API_HASH|PROXY_SECRET|SESSION)$/i`.
  Без этого фильтра шаблон `{{env "PLUGIN_TOKEN"}}` отправлял бы токен в Telegram, а редактор секретов
  его бы не поймал: он применяется к логам, а не к тексту сообщения. Это та же дыра, которую
  спецификация закрыла, убрав `config` из контекста, — просто через другую дверь. Фильтр стоит в
  `defaultRenderDeps`, через который идут все продакшен-вызовы.

**`connectBot` не покрыт юнит-тестами.** Для проверки нужны реальные учётные данные Telegram.
Поведение teleproto 1.229.0 сверялось чтением его исходников (`TCPMTProxy`, `auth.start`,
`users.getInputEntity`), а живую проверку делает `npm run e2e`. Если будете править этот модуль,
учтите: автотесты вас не поймают.

## Как расширять

**Добавить хелпер sprig.** Семантику Go — в `helpers/golang.ts` с тестом в `test/golang.test.ts`;
регистрацию — в объект `helpers` в `helpers/sprig.ts`, порядок аргументов как в sprig; кейс — в
`test/helpers-sprig.test.ts`; имя — в список в README. Хелперы вне списка не регистрируются
специально: Handlebars бросает `Missing helper`, а `template.ts` превращает это в читаемую ошибку.
Исключение, о котором стоит знать: вызов без аргументов (`{{uuidv4}}`) Handlebars не отличает от
опечатки в имени переменной и рендерит пустую строку.

**Добавить тип медиа.** Сейчас медиа-параметры дают ошибку конфигурации — список `UNSUPPORTED` в
`config.ts`. Нужно: убрать имя из списка и добавить поле в `Config`; расширить `TelegramGateway`
методом поверх `client.sendFile`; раскрыть путь к файлу в `main.ts` (в оригинале это glob).
Разметка и шаблоны не затрагиваются.

**Добавить ещё один CI.** Правится только `ci-context.ts`: новый источник переменных в `loadCiContext`
и фикстура в `test/ci-context.test.ts`. Имена полей `CiContext` менять нельзя — на них держится
контекст шаблона.

## Карта тестов

270 тестов, 13 файлов, без сети. Что гарантирует каждый:

| Файл | Что проверяет |
|---|---|
| `env.test.ts` | приоритет префиксов, пустое как незаданное, правила Go для bool и int |
| `config.test.ts` | умолчания, список недостающих параметров, запрет медиа, форматы proxy-секрета |
| `redact.test.ts` | маскирование всех вхождений, длинные секреты раньше коротких |
| `ci-context.test.ts` | соответствие Drone (включая `DRONE_STAGE_STARTED`), Actions и умолчания |
| `recipients.test.ts` | кейсы `parseTo` из тестов оригинала, `@username`, пропуск мусора |
| `golang.test.ts` | примитивы Go: длительности, Go-layout дат, QueryEscape, RE2-замены |
| `helpers-drone.test.ts` | 12 хелперов, блочные `success`/`failure`, обрезка по рунам |
| `helpers-sprig.test.ts` | подмножество sprig, целочисленные `div`/`mod`, `Missing helper` |
| `markdown.test.ts` | таблица кейсов парсера, оба отклонения, смещения UTF-16 на эмодзи и кириллице |
| `format.test.ts` | сборка `Api.MessageEntity*`, HTML, лимит 4096 |
| `template.test.ts` | **три реальных шаблона из `.drone.yml`**, порядок экранирования, фильтр секретов, правила raymond |
| `telegram.test.ts` | `waitForPort` на локальном TCP-сервере, `toPeer`, обратный отсчёт |
| `main.test.ts` | все ветки `run()` на фальшивом шлюзе: коды выхода, частичный отказ, маскирование, таймаут |

Самый ценный из них — `template.test.ts`: он прогоняет ваши настоящие шаблоны и сверяет текст и ссылки,
которые получит Telegram. Это и есть доказательство совместимости.
